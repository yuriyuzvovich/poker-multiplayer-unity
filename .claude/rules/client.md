# Unity client rules

## Assemblies and composition

- Every folder with code has an asmdef: `Infrastructure.<Area>`, `Features.<Slice>`, `App.Root`, `App.Editor`, tests.
  A feature asmdef references infrastructure, `Features.Table` and `Poker.Shared.dll` only; never another feature.
- DI is VContainer. `App/RootLifetimeScope.cs` is the composition root; each slice has a static
  `<Slice>Installer.Install(IContainerBuilder builder)` that registers its model, scene, presenters
  (`RegisterEntryPoint<T>()`) and views. Constructor injection only.
- App start runs as commands (`ConnectCommand`, `HelloCommand`, `SyncClockCommand`, `ReturnToTableCommand`) composed
  with `Infrastructure/Core/Commands` (sequence, parallel, retry, timed).

## Async and animation

- UniTask only; no coroutines, no `async void`. Pass a `CancellationToken` as the last parameter.
- Tweens are DOTween. Animations that react to the network go through the `PresentationQueue`
  (`Infrastructure/Core/Presentation`) as `IVisualCommand`s so network order and animation order stay decoupled.
- Money on screen changes only after the animation that explains it (`DisplayLock`/`DisplayHold`).

## Network

- Subscribe to server messages through `IServerConnection.Subscribe<T>(handler)` and dispose subscriptions with the
  presenter. Features take `IServerConnection`; only `App` (connection lifecycle) and diagnostics use the concrete
  `ServerConnection`. Requests go through the pending request map (request id, timeout, cancellation).
- The client never decides game outcomes; it sends intents and renders server facts.

## Views and assets

- MVP: presenters hold logic and talk to view interfaces; views (MonoBehaviours) only render and raise input.
- Views and popups load through Addressables (`ViewLoader`, `PopupService`, `LazyView`). Pool repeated views.
- Never create or edit `.meta` files by hand. After adding files under `client/Assets/`, ask the user to focus Unity so it
  generates them, and do not commit assets without their `.meta`.
- Scenes and prefabs are generated by editor builders (`MainSceneBuilder`, `UiPrefabBuilder`, `UiSkinBuilder`); change
  the builder and rerun it, do not hand-edit the YAML.
- Third-party code stays under `Assets/Plugins/` and is never edited.
